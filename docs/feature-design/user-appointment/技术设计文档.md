## 1. 后端接口设计

### 1.1 查询我的预约

| 项目 | 内容 |
|------|------|
| 端点 | GET /api/appointment/my |
| 认证 | JWT（从 token 中提取 userId） |
| 参数 | pageNum(默认1), pageSize(默认10) |
| 返回 | Result<IPage<Appointment>> |

现有 AppointmentMapper.selectPageWithParams 已支持 userId 过滤，直接复用。

### 1.2 取消预约

| 项目 | 内容 |
|------|------|
| 端点 | PUT /api/appointment/{id}/cancel |
| 认证 | JWT |
| 逻辑 | 校验预约属于当前用户 -> status改为0 -> cancel_reason设为"用户主动取消" |
| 返回 | Result<Void> |

## 2. Controller 设计

新建 AppointmentController.java：

- GET /api/appointment/my — 查当前用户预约分页
- PUT /api/appointment/{id}/cancel — 取消指定预约

实现要点：
- userId 从 JWT 中提取，与其他 controller 模式一致
- selectPageWithParams 已有 userId 过滤，直接复用
- 取消前校验：预约存在、属于当前用户、状态为1

## 3. 前端实现

### 3.1 新增页面

新建 userAppointments.vue，组件结构：
- el-table 展示预约记录，列：医生姓名、职称、日期、时段、状态、备注、操作
- el-tag 按状态显示不同颜色（已预约=warning, 已完成=success, 已取消=info）
- el-popconfirm 取消二次确认
- el-pagination 分页

### 3.2 API

在 frontend.js 中新增：
```js
export function getMyAppointments(params) { return service.get('/appointment/my', { params }) }
export function cancelAppointment(id) { return service.put('/appointment/' + id + '/cancel') }
```

### 3.3 路由与导航

- frontendRoutes 新增 path: 'appointments'
- FrontendLayout 导航中新增"我的预约"入口

### 3.4 兼容性注意事项

- /api/appointment/** 路径需要 SecurityConfig 放行给已认证用户
- 控制器的 /my 和 /cancel 不与已有的 AdminAppointmentController（/api/admin/appointment/**）冲突
