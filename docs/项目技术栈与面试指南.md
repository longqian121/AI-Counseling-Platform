# AI 心理健康助手：技术栈与面试指南

> 文档依据当前仓库的 `pom.xml`、`ai-vue/package.json`、配置文件和主要业务代码整理。它描述的是**当前实现**，而非理想设计；面试时应如实区分“已实现”和“可改进”。

## 1. 项目定位与 30 秒介绍

这是一个面向心理健康场景的前后端分离系统，包含普通用户、管理员、心理医生三种角色。普通用户可以进行 AI 心理咨询、记录情绪日记、浏览知识文章和预约医生；管理员可以管理内容、医生、咨询记录、风险告警和运营看板；医生可以查看预约、患者咨询总结和 AI 生成的就诊前简报。

项目的核心不只是“接一个大模型聊天接口”，而是把一次咨询沉淀成可管理的数据闭环：**流式对话 → 消息落库 → 风险评估 / 情绪分析 → 自动或手动生成总结 → 医生预约前简报 → 管理端质检与告警**。

## 3. 后端技术栈及其作用

### 3.1 Java 17 + Maven

- **Java 17** 是项目的语言与运行时版本，带来较新的 LTS 支持和语言 / JVM 能力。
- **Maven** 负责依赖管理、编译、测试和 Spring Boot 打包。依赖版本主要由 `spring-boot-starter-parent 3.5.16` 统一管理。
- 面试表达：项目采用 Maven 管理后端依赖，Java 17 运行 Spring Boot 3，避免 Jakarta 命名空间不兼容问题。

### 3.2 Spring Boot 3.5.16

Spring Boot 是后端应用的启动与自动配置框架。入口类 `AiSpringbootApplication` 使用 `@SpringBootApplication` 启动组件扫描和自动配置，并以 `@EnableScheduling` 启用定时任务。

它在本项目中负责：嵌入式 Web 服务、配置绑定（`application.yml`）、依赖注入、REST 接口、校验、安全和任务调度的整合。业务类依赖注入后形成 `Controller → Service → Mapper` 的调用链。

### 3.3 Spring Web + REST API

`spring-boot-starter-web` 提供 Spring MVC。Controller 使用 `@RestController`、`@RequestMapping`、`@GetMapping`、`@PostMapping` 等注解暴露 API，例如：

- `/api/user`：注册、登录、当前用户、退出；
- `/api/psychological-chat`：会话创建、流式聊天、历史记录和情绪结果；
- `/api/knowledge`：知识分类树和文章 CRUD；
- `/api/admin/**`、`/api/doctor/**`：后台、医生工作台；
- `/api/data-analytics`：管理端统计数据。

接口通过通用 `Result<T>` 包装返回，`GlobarExceptionHandler` 统一处理参数校验、业务异常和上传大小异常，前端因此能以统一的 `code / msg / data` 结构消费结果。

### 3.4 Jakarta Validation

`spring-boot-starter-validation` 结合 DTO 和 `@Valid` 校验请求参数。它将“输入是否完整、格式是否合法”的职责放在接口边界，而不是散落到业务代码中。例如情绪日记服务还会额外校验情绪分数为 1–10、睡眠与压力分数为 1–5。

价值在于尽早拒绝非法请求，并由统一异常处理器输出可读错误信息。

### 3.5 MySQL + MyBatis-Plus 3.5.15

- **MySQL** 是事务型关系数据库，存储用户、咨询会话、消息、情绪日记、文章、预约、风险告警、就诊前简报和质检报告。
- **MyBatis-Plus** 用 `BaseMapper` 和 `LambdaQueryWrapper` 提供单表 CRUD 与类型安全的条件构造，减少基础 SQL；带有统计、分页、关联需求的 Mapper 则保留自定义查询空间。
- 实体类使用 `@TableName` 对应数据库表，例如 `emotion_diary`、`knowledge_article`、`appointment`、`risk_alert`、`pre_visit_briefing`、`quality_report`。

当前 `schema.sql` 对情绪日记设置了 `(user_id, diary_date)` 唯一索引，因此 `EmotionDiaryService` 可以实现“同一用户同一天新增或更新一条日记”；文章、预约、告警等查询字段也建立了普通索引。

> 注意：POM 同时引入了 `spring-boot-starter-data-jdbc`，但仓库中的实际数据访问代码主要使用 MyBatis-Plus，而不是 Spring Data JDBC Repository。这一点应如实说明。

### 3.6 Spring Security + JWT + BCrypt

认证与授权采用无状态方案：

1. 登录时，`UserService` 用 `BCryptPasswordEncoder.matches` 校验散列密码；
2. 验证通过后，`JwtTokenUtil` 把用户 ID、用户名、角色类型签入 JWT；
3. 浏览器把 Token 放在请求头 `token`；Axios 请求拦截器自动注入；
4. `JwtAuthticationFilter` 继承 `OncePerRequestFilter`，对非公开接口验证 Token、检查账号状态，并把 `ROLE_角色值` 写入 `SecurityContext`；
5. `SecurityConfig` 关闭服务端 Session，配置为 `STATELESS`，公开登录、注册、部分知识文章和上传资源路径。

三类角色的枚举值是：`1=普通用户`、`2=管理员`、`3=心理医生`。前端路由守卫根据 `userInfo.userType` 把用户导向用户端、后台或医生端。

面试时可强调：JWT 解决了前后端分离场景下的无状态身份传递，BCrypt 避免明文存储密码；服务端仍会查一次用户状态，因此禁用用户能立即失效，而不必等 Token 到期。

### 3.7 Spring AI 1.0.3 + DeepSeek（OpenAI 兼容协议）

这是 AI 能力的核心。项目引入 `spring-ai-starter-model-openai`，但将 OpenAI 客户端的 `base-url` 指向 DeepSeek 的兼容接口。`ChatClientConfig` 按用途创建三类 `ChatClient`：

| 客户端 | 主要用途 | 机制 |
|---|---|---|
| `openAiChatClient` | 心理陪伴式对话、咨询总结 | 带默认心理疏导系统提示词和 30 条消息窗口记忆。 |
| `deepseekChatClient` | 风险评估 | 让模型按提示词返回 JSON，代码解析风险等级、类型、证据和建议。 |
| `deepseekReasonerClient` | 就诊前简报、质检 | 使用推理模型对多来源历史数据归纳，或对对话抽样评分。 |

关键实现包括：

- **提示词约束**：`PromptMessage` 将心理支持、风险评估、总结和质检任务分成不同系统提示词，降低一个泛化 Prompt 同时承担所有任务的失控风险。
- **短期记忆**：`MessageWindowChatMemory.maxMessages(30)` 以 `conversation-sessionId` 为会话键保存近期上下文，避免每轮都携带全部历史。
- **结构化结果的轻量解析**：风险评估先截取 JSON 再用 Hutool JSON 解析；总结和简报则从 `【主要问题】` 等固定段落标题中提取字段，原始结果也会保存，便于追溯。
- **工具调用（Function Calling）**：`AgentToolService` 的 `@Tool` 方法被注册给聊天客户端。模型可调用“医生列表、可用时段、创建 / 取消预约、查询预约”等受控函数，真正的数据写入仍在 Java 服务中完成，而不是让模型直接操作数据库。

### 3.8 Reactor Flux + SSE 流式输出

心理聊天接口声明 `produces = text/event-stream`，后端以 `Flux<ServerSentEvent<String>>` 逐片推送模型输出。前端使用 `@microsoft/fetch-event-source` 消费事件流，边接收边展示。

流式设计的价值是把首字延迟显著降到“模型生成第一段后即可显示”，避免用户等待整段回答完成。服务端同时用 `StringBuilder` 拼接完整回复，在流结束时将 AI 消息落库，并可触发后续情绪分析、风险评估等动作。

### 3.9 异步编排与定时任务

- **`CompletableFuture.runAsync`**：风险评估和就诊前简报异步执行，不阻塞主聊天响应或预约接口。风险等级达到 3 以上时写入 `risk_alert`。
- **`ConsultationAutoCloseTask`**：每分钟扫描活跃会话；最后一条消息超过 10 分钟则自动生成咨询总结并将会话改为完成。
- **`QualityInspectionService`**：每天凌晨 2 点汇总前一天的会话数、风险告警、高风险次数；再随机抽样（最多 10 条）让模型评分共情、相关性、安全性，并归类高频问题、标记需复核会话。

面试中要指出：当前异步任务使用默认线程池，适合原型但难以做容量隔离、重试和可观测性；生产环境应换成配置化的 `TaskExecutor` / 消息队列，并加入幂等、失败重试与告警。

### 3.10 文件上传与静态资源映射

`FileUploadController` 接收图片上传，校验文件非空和 `image/*` MIME 类型，按业务类型、年月和 UUID 落到本地 `uploads` 目录，同时在 `sys_file_info` 保存元数据。`WebMvcConfig` 将 `/uploads/**` 映射为本地文件资源，文章封面可直接访问。

### 3.11 Hutool 与 Lombok

- **Hutool**：本项目主要用 `JSONUtil / JSONObject` 做模型 JSON 解析，`AntPathMatcher` 做公开路径匹配，减少工具代码。
- **Lombok**：通过 `@Getter`、`@Builder` 等注解减少实体、DTO 的样板代码；Maven 编译插件已配置注解处理器。

## 4. 前端技术栈及其作用

### Vue 3.5 + Vite 7

Vue 3 使用单文件组件（`.vue`）构建界面；Vite 负责本地开发、热更新和生产打包。`vite.config.js` 配置了 `@ → src` 别名，并把 `/api` 代理到后端 `http://localhost:1236`，解决开发阶段跨域问题。

### Vue Router 4

路由分为三组布局：

- `/`：普通用户端（咨询、情绪日记、知识库、预约）；
- `/back`：管理员端（看板、文章、咨询、情绪、医生、预约、告警、质检）；
- `/doctor`：医生端（今日预约、全部预约、患者总结）。

懒加载 `() => import(...)` 将页面拆成按路由加载的代码块。全局守卫在前端做基础的登录 / 角色跳转；真正的安全边界仍应由后端完成。

### Element Plus + 图表与编辑器

- **Element Plus + Icons**：提供表格、表单、对话框、菜单、分页、消息提示等后台管理 UI 组件，提高交付速度和视觉一致性。
- **ECharts**：用于管理端统计看板，把 7 天情绪趋势、会话趋势和用户活跃度等聚合数据可视化。
- **wangEditor**：为知识文章提供富文本编辑能力；`RichTextEditor.vue` 是封装组件。
- **Sass**：支持样式变量、嵌套和模块化维护。

### Axios + Fetch Event Source + Pinia

- **Axios**：`utils/request.js` 统一配置 `/api` 前缀、5 秒超时、Token 注入与响应码处理；遇到认证失效会清理浏览器本地状态并跳转登录页。
- **@microsoft/fetch-event-source**：消费 POST 形式的 SSE 流，适合 AI 流式回复；原生 `EventSource` 只能 GET，无法直接传递聊天请求体。
- **Pinia**：当前用于如后台侧栏折叠的跨组件 UI 状态。登录信息目前放在 `localStorage`，而非 Pinia 持久化状态。

## 5. 核心业务链路：面试应能讲清楚

### 5.1 AI 心理咨询与安全治理

1. 用户登录后创建咨询会话，首条消息先写入 `consultation_message`；
2. 用户发送消息，请求进入 SSE 流式接口；
3. 服务根据 session ID 建立记忆上下文，配置心理支持系统提示词，并向模型注册预约工具；
4. 模型文本分片实时返回前端；完整回复落库；
5. 风险评估服务异步让模型输出结构化 JSON；中高风险（`riskLevel >= 3`）写入告警表供管理端处理；
6. 会话结束后生成结构化咨询总结；长期不活跃会话可由定时任务自动关闭并总结。

这条链路体现的设计原则是：**生成式模型负责理解、陪伴与归纳；关键事务（预约、持久化、权限）由确定性的后端代码执行；风险信息可留痕并进入人工复核流程。**

### 5.2 AI 工具调用预约

当用户在聊天中说“帮我约医生”，模型不会自行编造结果：它调用被 `@Tool` 标注的方法，后端检查医生状态、预约日期（限定今天起 14 天）、有效时段和已占用时段，确认后才写入 `appointment` 表。预约成功后会异步汇总历史咨询总结、情绪日记、情绪分析和风险告警，调用推理模型生成医生可看的就诊前简报。

### 5.3 管理端数据分析和 AI 质检

`DataAnalyticsService` 直接从用户、日记、会话、消息等表聚合出总数、7 日趋势、平均情绪评分、平均会话时长和活跃数据，前端用 ECharts 呈现。

质检任务每天评估前一天已完成会话的抽样质量，并输出共情、相关性、安全性、综合评分、高频议题和需复核会话。这是“模型不仅面向用户，也参与内部运营治理”的设计点。

## 7. 面试高频问题与参考回答

### Q1：为什么用 SSE，而不是普通 HTTP 或 WebSocket？

该场景主要是服务端单向持续输出模型文本，SSE 更轻量、基于普通 HTTP、浏览器和代理兼容性好。普通 HTTP 要等全文生成完，体验不好；WebSocket 适合更强的双向实时协作，但这里复杂度没有必要。前端使用 fetch-event-source 是因为聊天请求需要 POST JSON 请求体。

### Q2：AI 的上下文如何管理？会不会无限增长？

按会话 ID 划分记忆，`MessageWindowChatMemory` 最多保留 30 条消息，以窗口截断控制 Token 成本。完整会话仍持久化到数据库，结束后生成总结；进一步可以把“历史原文 + 总结”结合，或加入向量检索，避免长期上下文丢失。

### Q3：如何避免模型越权创建预约？

模型只能选择是否调用工具和填写参数，不能直接写数据库。工具方法在服务端验证医生状态、日期范围、时段合法性与占用情况，随后才执行写入。生产环境还应在数据库增加 `(counselor_id, appointment_date, time_slot)` 唯一约束，并用事务处理并发抢号。

### Q4：风险识别为什么要异步？

风险识别依赖额外一次模型调用，如果同步等待会增加聊天首包和整轮响应时间。当前方案异步执行，告警落库后管理员可查看。高风险生产场景还应加入规则兜底、任务队列、重试、人工升级机制和明确的紧急服务提示，不能把模型分数当成医疗诊断。

### Q5：如何实现权限控制？

登录生成 JWT，过滤器校验签名、过期时间和用户状态，再将角色写入 Spring Security 上下文。前端路由守卫只是体验层的跳转控制，不能替代后端授权；后端应继续在 Controller / Service 使用 `@PreAuthorize` 或显式的资源归属检查。

### Q6：项目有哪些可量化的性能 / 可靠性改进？

可以从四点回答：数据库分页与索引、LLM 调用超时 / 限流 / 重试、异步任务改为专用线程池或消息队列、统计数据预聚合或缓存。还应为模型调用、SSE 连接、异步任务和风险告警建立日志、指标与追踪。

## 8. 当前代码中应主动说明的改进点

这部分不是否定项目，而是体现工程判断力。被问到不足时可以按“问题 → 风险 → 改进”回答。

| 当前情况 | 风险 | 建议改进 |
|---|---|---|
| 数据库密码、JWT 密钥、模型密钥直接出现在开发配置文件中 | 泄露风险，无法按环境隔离 | 移到环境变量或密钥管理服务；提交前轮换已经暴露的密钥。 |
| 前端只按角色做路由跳转，后端部分管理 / 医生接口未见细粒度方法级角色校验 | 登录用户可能访问不属于自己的资源 | 用 `@PreAuthorize`、资源归属校验和集成测试保证服务端授权。 |
| `CompletableFuture.runAsync` 使用默认公共线程池 | LLM 慢请求可能挤占公共线程，失败难追踪 | 配置专用 `TaskExecutor`，设置超时、重试、熔断和任务状态。 |
| 预约先查后写，表定义未见同一医生同一时段唯一约束 | 并发请求下可能重复预约 | 加联合唯一索引、事务与冲突处理。 |
| 模型结构化输出用截取 JSON / 正则分段解析 | 模型格式漂移会导致解析失败 | 用 JSON Schema / Structured Output，保留校验和降级策略。 |
| 文件上传主要校验 MIME 前缀，且文件放本机磁盘 | MIME 可伪造，单机文件不利于扩展 | 校验文件魔数，限制扩展名，使用对象存储和病毒扫描。 |
| 统计活跃用户当前取日记用户与咨询用户数量的较大值 | 同时活跃用户的真实并集可能不准确 | 在 SQL 用 `UNION DISTINCT` 或应用层用 `Set<Long>` 计算并集。 |
| 自动总结可能重复执行 | 多次任务扫描可能产生重复总结 | 对 `session_id` 设唯一约束，并在事务中使用状态机或幂等锁。 |

## 9. 建议的项目讲述顺序

1. 先说明业务目标：面向心理健康场景，连接用户、AI、医生和管理人员。
2. 再讲技术架构：Vue 3 + Spring Boot + MySQL，前后端分离；Spring AI 接 DeepSeek。
3. 选一个最有技术含量的闭环讲透：SSE 流式咨询、工具调用预约、异步风险评估和自动总结。
4. 说明安全与数据沉淀：JWT、BCrypt、消息 / 日记 / 告警持久化、医生简报。
5. 最后主动提出生产化改进：密钥管理、后端 RBAC、预约并发控制、异步任务治理和模型输出校验。

## 10. 本地启动速记

后端需要 Java 17、Maven 和可连接的 MySQL；前端需要 Node.js。启动前应按实际环境配置数据源和模型连接信息，且不要把真实密码或 API Key 写回版本库。后端默认端口为 `1236`，Vite 开发服务器会将 `/api` 转发到该端口。
